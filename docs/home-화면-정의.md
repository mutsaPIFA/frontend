## 이 화면은 뭔가

하단 탭 4개 중 하나. **MCM 상품을 그냥 둘러보는 공간**이다.

```
home(상품보기) · closet · style · profile
```

추천·스타일링과 **무관하게** MCM 카탈로그를 탐색한다. "내 옷장에서 시작해 MCM을 더한다"는 제품 컨셉에서, **MCM을 만나는 입구** 역할.

## API

**진입 시 `GET /api/v1/mcm-products` 한 번만 호출**하고, 검색·탭 전환은 **클라이언트에서 필터링**한다.

- 시드 규모가 150~200개라 전체를 받아도 JSON 40KB 수준(이미지는 URL만)
- 탭 전환이 즉각 반응하고 네트워크 왕복이 없다
- 서버에 `query`·`category` 파라미터도 있지만 **v1 프론트는 쓰지 않는다**

응답 형태와 필드는 → [`docs/api-v1.md` §2-1](https://github.com/mutsaPIFA/docs/blob/main/api-v1.md)

### 카테고리 탭 ↔ `category` 매핑

서버가 주는 `category`는 7분류다. 탭은 이렇게 묶는다:

| 탭 | 포함 `category` |
|----|----------------|
| 전체 | 전부 |
| BAGS | 가방 |
| ACC | 악세서리 |
| CLOTHES | 상의, 하의, 아우터, 원피스, 신발 |

> 7분류를 4탭으로 줄인 이유: MCM은 가방 비중이 압도적이라 7탭이면 대부분 비어 보인다.
> 단, **서버·스타일링 로직은 7분류를 그대로 유지**한다(코디 조합에 상의/하의/아우터 구분이 필요). 탭은 순수 UI 묶음.

## 상품 카드에서 하는 것

| 동작 | 결과 |
|------|------|
| 카드 탭 | 화면 6 제품상세로 이동 |
| ♡ 찜 | **v1 제외 — 아이콘 노출하지 않음** |

찜을 뺀 이유: 핵심 루프(옷장→DNA→추천→코디)에 걸리지 않고, 화면 6의 '옷장에 담기'가 유사 역할을 이미 한다.

## 화면 6 제품상세에서 이어지는 것

| 버튼 | 동작 |
|------|------|
| 옷장에 담기 | `POST /closet-items {mcmProductId}` → 내 옷장에 `source=MCM`으로 추가 |
| 이 제품으로 코디 | `POST /outfits {moodId, seedMcmProductId}` → 화면 16 |
| **구매하기** | **`productUrl`로 MCM 공식몰 이동** (앱에서 결제하지 않음). 인앱 브라우저 권장 |
